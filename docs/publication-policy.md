# Polityka publikacyjna programu ARC

ARC utrzymuje mapę kierunków badawczych, projektów, manuskryptów i zależności oraz może prowadzić **lokalne kanoniczne manuskrypty**. Nie zastępuje zewnętrznych `msc-*`, `app-*`, `lib-*` ani magazynów danych. Rejestry `portfolio/*.json` są źródłem prawdy dla programu, natomiast uprawnienia do upublicznienia każdej pozycji i jej dowodów należy oceniać oddzielnie.

## Cztery niezależne zdarzenia

1. **Publiczna strona GitHub Pages:** wyłącznie ręcznie zatwierdzona projekcja `pages/`, bez `docs/`, instrukcji agentów, prywatnych wpisów i danych. Zasady: [GitHub Pages](pages.md).
2. **Wydanie GitHub Release:** wersjonowana migawka katalogu ARC albo pakiet odtwarzalności, nie automatyczna publikacja artykułów. Zasady: [Wydania ARC](releases.md).
3. **Publikacja naukowa:** preprint, zgłoszenie, akceptacja i publikacja manuskryptu wymagają dowodów w kanonicznym `msc-*`, zgody autorów, zasad czasopisma i rzeczywistego DOI/URL.
4. **Udostępnienie danych:** oddzielna ocena zgód, etyki, prywatności, licencji, ryzyka reidentyfikacji oraz właściwego repozytorium z kontrolą dostępu.

`submitted`, `accepted` i `published` nie są synonimami. Status może zostać ujawniony dopiero po zweryfikowaniu odpowiedniego `stage_evidence`. Nie wpisuj fikcyjnych DOI, certyfikatów, wyników i deklaracji odtwarzalności. Ograniczenia embarga, licencji i praw czasopisma obowiązują niezależnie od stanu repozytorium. **Każda publikacja wymaga odrębnej decyzji właściciela** i kontroli jej docelowego zakresu.
