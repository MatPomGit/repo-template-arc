# Reagowanie na incydent

**Stan:** procedura planistyczna, bez skonfigurowanego dyżuru.

W razie podejrzenia ujawnienia metadanych prywatnego projektu, danych uczestników, sekretów albo uprawnień hosta, przerwij **tylko** własne niebezpieczne działania, zabezpiecz niezbędne dowody i przekaż zgłoszenie prywatnie upoważnionemu właścicielowi. Nie publikuj incydentu w otwartym Issue i nie usuwaj historii Git ani zdalnych zasobów bez zgody.

Ustal zakres i commit SHA ujawnienia, widoczność repo i Pages, kopie w wyszukiwarkach, wystawione poświadczenia i potrzeby ochrony danych. Właściciel podejmuje decyzje o ograniczeniu dostępu, obrocie sekretów, powiadomieniach, remediacji i walidacji, zgodnie z rzeczywistymi uprawnieniami oraz obowiązującymi obowiązkami prawnymi.

Raport końcowy powinien podawać faktyczny wynik i działania naprawcze, a publiczna wersja musi być pozbawiona informacji chronionych. Zobacz [SECURITY.md](../../SECURITY.md) i [model zagrożeń](threat-model.md).
